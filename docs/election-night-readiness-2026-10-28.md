## Deployment and storage handoff

**Before changing the running Render service, privately export the current runtime files.** A disk declaration in source does not copy data from an older ephemeral instance, and an existing dashboard-created Render service may require the settings to be applied explicitly.

| Existing path | Destination beneath RESULTS_STORAGE_DIR | Purpose |
| --- | --- | --- |
| `.runtime/results-state.json` | `results-state.json` | Last-good provider races, health, private audit and committed call envelope |
| `data/result-calls.json` | `result-calls.json` | Calls, overrides, grace/hold and automation settings |
| `data/live-results-races/` | `race-details/` | Sparse race history/details |
| `.runtime/county-history/` | `county-history/` | Sparse county history |

Preserve the matching calls and runtime state together. If committedCalls is already present, that envelope is authoritative on recovery. Do not replace a populated disk with older repository snapshots. Keep the export private: it can contain overrides, pending calls and audit records. Keep a backup before migration; validate candidate identity, call source and vote totals against the pre-deploy public snapshot after startup.

The declared Render disk uses mount path `/var/data/election-results`; RESULTS_STORAGE_DIR must point to that exact mounted directory. The build audit runs before deployment. Render disks are runtime mounts; build-time file existence does not prove the mount or migration. This pass did not purchase/apply a disk, inspect the account, or certify a production deployment. Confirm the account's disk/cost and single-instance/deploy behavior in Render before applying it.

The optional existing GitHub backup path now exports **published calls only**, excluding pending automation, manual override flags and private audit. It is not a high-frequency result database and cannot recover full runtime state, vote history or county history. A published NBC backup preserves NBC attribution and holds source verification for review. It is not a substitute for the mounted disk.

What does not survive without other storage: process-local delta versions/snapshot cache (clients reset/refetch safely), projection queue/toasts, hover, temporary highlights and poll-wave display. Activity is intentionally session-local. Geometry/detail caches rebuild lazily. Pins, saved/custom themes, panel size and safe view state are browser-local; cleared browser storage/private sessions lose them, and separate devices do not sync them. Same-origin tabs share saved browser preferences by design. The independent-client test used separate origins to model separate devices, not a claim of isolated storage between same-origin tabs.

## Design/source review and adopted principles

Adopted general principles: separate vote-count progress from projection authority; keep published calls distinct from ordinary leader changes; preserve geographic drilldown; surface recent observed changes without recoloring party results; make unresolved contests easy to find; keep temporary information compact and dismissible. No brand-specific graphics were copied.

AP's official methodology supports the counting-versus-calling distinction and the need to identify progress metrics accurately: [How AP counts the vote](https://www.ap.org/elections/our-role-in-the-u-s-elections/how-ap-counts-the-vote/). NBC's official election overview was reviewed at the source-description level: [NBC News election coverage](https://www.youtube.com/watch?v=S5Q3DT42QbM). NYT's public precinct-map repository supplied geographic context, not evidence of a complete live interface review: [NYT 2024 precinct map](https://github.com/nytimes/presidential-precinct-map-2024).

A full current visual review of NYT/NBC/CNN election interfaces was not completed: page retrieval was restricted, and the direct NYT browser attempt was blocked by browser site-safety policy. No alternate access workaround was attempted. Interface comparisons requiring those pages remain manual, and this report does not call them passed.

Poll-close provenance is embedded in `data/results/poll-closes.json`, using the reliable [2026 270toWin closing-time table](https://www.270towin.com/poll-closing-times/). It explicitly documents whole-state versus district handling, split geography limits and November standard time. Election Day court/local extensions require a fresh source check; this pass did not establish a precinct-level official closing registry.

Persistence assumptions were checked against official [Render disk documentation](https://render.com/docs/disks) and [Blueprint disk specification](https://render.com/docs/blueprint-spec). These document platform behavior; they do not establish that FEA's running service currently has a disk.
