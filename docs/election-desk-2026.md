# Election night desk: polish and performance pass

Implemented and locally verified October 27, 2026. This report follows the 23 requested completion items. No deployment or Render account setting was changed. The NBC verification gates, grace period, hold/ignore rules, manual authority, audit and OBS call source remain authoritative.

1. **Race-card design.** Added deliberate raised surfaces, stronger title/candidate hierarchy, party rails, tabular aligned numbers, restrained row separators and visible focus styles. Results stays compact: candidates, expected vote/precinct reporting, current margin and last update. Additional descriptive measures are behind More metrics. Race navigation, the map, all panel views and alerts remain on the same page.

2. **Projection banner.** The banner now has a small NBC PROJECTS or FEA PROJECTS source label, prominent candidate, party/race context, accent rail and actual call time in Eastern time when available. The projected candidate gets a check in the ordinary results table. NBC auto-acceptance remains attributed to NBC. A statewide call is no longer shown as a separate county projection in county hover rows.

3. **Projection notifications.** A shared published-call tracker emits one client call-change event consumed by the toast and map pulse. It uses only public `calls`; private provider projections and pending state do not enter the public feed. View race switches office, focuses geography and opens details without leaving the dashboard. Initial historical calls do not flood the page; session storage retains fingerprints across reloads. New/changed/withdrawn observed public calls have distinct identities. Corrections and retractions use amber Projection update cards. Alerts are polling-driven, not a replay of the entire audit ledger.

4. **Multiple calls.** Desktop/tablet displays at most three cards; phone displays one. Additional calls remain in a bounded visible queue control such as +7 more projections, which advances through them. Cards normally dismiss after 18 seconds. Hover/focus pauses dismissal; a focused alert remained visible beyond its normal timeout in browser QA. The 3-call and 10-call lab cases were exercised, including overflow and cross-office View race.

5. **Animations.** Added short toast entrances, published-geography highlights, winner-check entrances, changed-number fades, changed-county highlights and chamber-width transitions. Ordinary updates do not replay an unchanged winner indicator. There is no confetti or endless pulse. CSS animations/transitions and D3 zoom durations respect reduced-motion preference. Chart point inspection supports pointer/touch across the plot and keyboard focus, with a textual result summary.

6. **Resize restoration.** Restored the existing `bindFocusPanelResize()` and supplied a visible bottom-right grip. Mouse/pointer resize was exercised. The grip has keyboard arrow resizing and Home reset; double-click also resets. Minimum dimensions and viewport bounds apply. Internal panel content scrolls; the page does not.

7. **Size persistence.** Width/height persist in local storage and restore when another race is opened or the page reloads, constrained to the new viewport. The exercised 520 × 567.9 window restored to the same dimensions. Position is not persisted. Facts adapt to a wider container and charts use the available width. Small-screen bottom sheets have no resize grip.

8. **County lock.** A county click or keyboard activation locks the county and outlines it. The Counties list provides an alternative when geography is covered by a window. Clicking it again, Clear county or Escape unlocks it; the first Escape keeps the race window open. Lock state survives normal result updates and view switches. Phone map selection was verified using an unobscured county target, and the final screenshot matrix uses an explicitly verified Adams County selection. Overlay-covered counties correctly do not receive clicks through the window.

9. **Advanced views.** Added Results, Counties, Trends and Demographics. Counties is present only when the race actually has county results. The default remains Results. Race search accepts full names, office abbreviations, district labels and candidate surnames; selecting a suggestion or pressing Enter stays in the dashboard. `/` focuses search. Map actions have race labels and keyboard activation. Floating controls move out from under a desktop race window, and notifications avoid both controls and the window. Phone watch/search stays available with the drawer collapsed; expanding it prioritizes the detailed view and uses a compact alert strip.

10. **Vote-history charts.** The existing race-detail `voteHistory` is the canonical source. D3 renders selectable total-vote, candidate-share, D−R margin and expected-vote charts. Missing expected-vote history is not relabeled from precinct history. Fewer than two useful observations show Waiting for more results. Inspection reports time, all available candidate totals/shares, margin and genuine expected vote. These are observed count changes, not forecasts.

11. **County history.** Added sparse append-only per-race/per-FIPS NDJSON in ignored runtime storage. Only changed candidate totals or reporting fields append a record. Restart deduplication and unchanged-file size were tested. Reading a county does not transfer other counties' history. It is never embedded in the national response. The adapter has normalized county candidate totals, FIPS and reporting fields sufficient to support this when a verified live source supplies them; no actual 2026 general-election county feed is claimed to have been captured.

12. **Descriptive metrics.** Added counted votes, D−R raw/percentage-point margins, change from the preceding observation, latest added votes and their candidate shares, valid 2024 shift, count relative to the comparable 2024 presidential total, and county contribution to the statewide raw margin. Estimated remaining votes use a genuine expected-vote percentage and are visibly approximate. Precinct reporting alone cannot produce that estimate. Negative corrections and roster changes do not produce misleading added-vote shares. Missing/invalid inputs hide the measure. Comparing counted office votes with the 2024 presidential total is not an eligible-voter turnout rate. House never uses statewide presidential data; all 435 House presidential comparisons remain unavailable pending verified district geography/baselines.

13. **Demographics.** Built real [2024 ACS 5-year data](https://www.census.gov/data/developers/data-sets/acs-5year.html) from official [Census bulk tables](https://www2.census.gov/programs-surveys/acs/summary_file/2024/table-based-SF/data/5YRData/), with official geography names. This avoids the API credential requirement while remaining a build-time task. The completed dataset has 3,222 county/county-equivalent and 52 state/territory records, including Puerto Rico; every mapped county joins. The 50-state-plus-DC population sum matches the published U.S. control, 334,922,499. Fields are population, White non-Hispanic, Black alone, Hispanic/Latino, Asian alone, age 65+, bachelor's degree+, and median household income. State figures are direct estimates. Race/ethnicity overlap and education's 25+ denominator are disclosed. Suppressed estimates are omitted. No party registration, commercial DDHQ data or district demographic approximation was added. Source files, prefix hashes, variables, definitions and build time are recorded in the artifact and [data guide](../data/results/README.md).

14. **Light theme.** Off-white canvas, neutral light context geography, white raised cards, dark text, deliberate controls, pale table/call surfaces, visible selected outlines, chart axes/lines, tooltips and alerts. Both ordinary election views and actual Census values were captured in light mode.

15. **Dark theme.** Separated canvas, panel and raised-control luminance with semantic tokens for background, border, primary/secondary text, hover and chart line. Panels separate through contrast and restrained static shadows. FEA's control blue and periwinkle accents remain. Text and labels do not rely on party color alone.

16. **Initial payload measurements.** The repeatable [file audit](election-desk-payloads.json) compares HEAD with the working tree, preserving Windows checkout line endings. A cold House entry's own required assets total approximately **43.83 MB → 5.87 MB raw**, or **9.87 MB → 1.51 MB gzipped** (about 85% less compressed data). This excludes external D3/TopoJSON/font/icon requests and the old board's idle preloads of up to 16 district maps, so it is not a production HAR or a complete browser page-weight claim. The House display geometry is now **1,303,985 bytes on the wire**, with every source feature retained and every district polygon nonzero. A selected Ohio county map is **78,462 bytes gzipped**, instead of transferring the whole 28.32 MB raw / 8.49 MB gzipped national county file. Static demographics is about **100 KB gzipped**, only on demand. Additional UI code/CSS makes those small assets larger; it adds no large chart library.

17. **Repeated-poll measurements.** In isolated before/after HTTP servers using the same unavailable-feed catalogue, ten old-client-style unconditional checks transferred **3,635,360 body bytes**. Ten new conditional version checks returned **304 with zero body bytes**. Headers still consume bandwidth. The measured one-published-FEA-call delta was **873 bytes** and contained only CO-04. The payload model's one-vote-race delta is 725 bytes. Full initial/recovery responses remain available. Local before/after response bodies were 363,536 bytes identity versus 25,142 bytes gzip (316,143 decoded). This is not a claim about Render's prior edge compression; hypothetical equal-compression summaries can be slightly larger because per-race version hashes are less compressible.

18. **Version/delta architecture.** Initial GET `/api/live-results`; then conditional GET `/api/results-version` every 15 seconds; when changed, GET `/api/live-results/changes?since=<opaque-version>`. Deltas carry changed summaries, removed IDs and a changed public provider warning. Chamber totals derive from those same published calls rather than a competing chamber state. Unknown/expired cursors return `reset: true` and the client fetches a full snapshot. Only 120 meaningful snapshots are retained; unchanged races are structurally shared, and repeated version checks against one cache object do not rehash the whole nation per viewer. Race details have independent ETags/version-based invalidation. An offscreen-updated race cannot reopen stale; a failed selected-detail fetch retains the last county/history data and retries even when the next national version is unchanged.

19. **Render resource changes.** Precompressed, content-hashed `.json.gz` maps/demographics and versioned JS/CSS get immutable caching. `.gz` is eligible for Render's Common static files edge-cache setting; ordinary JSON is not eligible under that setting. APIs use private revalidation or no-store, ETags and useful Last-Modified headers. Brotli/gzip responses use a bounded 24 MiB/80-entry compressed-response cache; conditional NBC bodies are bounded at 32 MiB/128 sources, with a 16 MiB per-body cache limit. Upstream If-None-Match/If-Modified-Since reuse only successfully parsed payloads; stale upstream timestamps remain stale. Source verification still runs before every request. The existing blueprint uses a Starter service. Enable/verify edge caching in the Render dashboard if desired; no account setting or CF-Cache-Status was verified here. See [Render's cache eligibility documentation](https://render.com/docs/web-service-caching). Persistent storage is still needed for runtime calls/history. No live vote-update GitHub commit loop or database was added.

20. **Map-render performance.** Ordinary deltas preserve the SVG, transform, selected race/county and window dimensions. They update changed fills/values instead of refitting/rebuilding geography. Selected county fills retain last-good data while a detail refresh is in flight, avoiding a neutral-map flash. County tooltip closures receive the fresh detail. A concrete existing tooltip bug was fixed: missing counties displayed statewide vote totals; they now show missing values, and known zero votes are rendered as zero. Initial geometry is compact; state county geometry, per-race detail/history and demographics are lazy. Structural changes, office changes, comparison changes and viewport resizing can still legitimately rebuild a map.

21. **Admin.** Overview is three concise metrics: feed/update age, waiting calls, FEA overrides, followed by Needs attention. Calls emphasizes source, race, candidate, ordinary state wording and Publish now/Hold/Override. Races leads with candidate totals and actual reporting/calls. Optional attachment/test copy is plainer. IDs, URLs, poll times, raw call state, audit, cache/version and backup details remain in Advanced. Manual publication and return-to-NBC were exercised through the refactored console in the isolated copy. No live feed was labeled connected to improve the demo.

22. **Verification.** `npm run test:results`: **48 passed** at final implementation verification; ratings regressions: **2 passed**. Coverage retains NBC gates, grace, persistence, holds/ignore/manual authority, outage handling, audit, OBS, watch metadata and strict House baseline behavior. New tests cover stable versions/deltas/reset, public payload privacy, county-only invalidation, event deduplication/corrections, descriptive math, sparse history/restart, official Census controls/coverage, missing/suppressed values, source-key parsing, optimized House coverage, client recovery/state preservation, last-good detail retries and county tooltip correctness. Browser checks covered both themes at 1366×768, 1920×1080, 2560×1440, 820×1180 and 390×844, with no page overflow. Captures include no selection, selected/counting, called, trends, locked county, real Census demographics and multiple alerts. Additional checks exercised pointer resize, exact dimension restoration, keyboard reset/Escape, menu/theme, search/navigation, focused alert retention, burst navigation and the actual public polling path's retraction alert. The latter was a temporary approved FEA call, not a fabricated NBC projection. Syntax and diff whitespace checks accompany the final handoff.

23. **Remaining real-data/hosting work.** The NBC 2026 general-election payload and Decision Desk projection field still need source verification and configuration, all races must be mapped, and the provisional candidate roster still needs certification. Live county arrays/history, expected vote and advanced count metrics are available only when that verified source actually supplies the necessary fields. Initial current general-election history is empty; the lab's vote/history/call examples are explicitly simulated. State/county Census data is real and complete for the documented vintage. District presidential baselines and the previously disabled historical comparisons remain unverified/hidden. Production load/CPU/RSS, edge-cache hits, persistent-disk recovery, deployment and the hosted public/admin/OBS path have not been certified by these local checks.
